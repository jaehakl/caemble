# 구조 FEA·운전 터빈 검증 기록

이 문서는 구현 범위와 실제 실행 증거를 연결한다. 실행 가능한 입력 계수,
Material Model, Solver method와 예제의 원본은 Catalog SQLite에만 있다.
각 결과의 입력·소스 snapshot과 큰 시계열은 아래 `.work` 경로에 보존했다.
그 경로는 이번 로컬 검증 산출물이며 Git에 포함되는 기준 데이터가 아니다.

**현재 상태: Solver·운전 예제 구현과 기본 회귀·전송 검증을 완료하고,
사용자 요청에 따라 장시간 운전 오차·수렴 검증은 후속 작업으로 남긴다.**
300초 운전의 최종 합격이나 전체 적용 범위의 정확도 검증을 완료했다고 표시하지
않는다. 아래 v6 운전 결과는 타워 감쇠 수정 전 진단 자료이며, v7 결과와 구분한다.

OpenFAST v5.0.0의 `TwrFADmp`와 `TwrSSDmp`는 나셀·회전자 질량을 제외한
타워의 고유진동수를 기준으로 감쇠행렬을 만든다. v6는 전체 결합 모델의 첫
fore-aft 모드 감쇠비에 맞춰 변환했기 때문에 타워 단면의 강성 비례 감쇠가
약 6.4배 컸다. 공식 소스의 고립 타워 모달 질량·강성으로 다시 변환하며,
변환 전 체크포인트는 물리 입력이 달라진 실행에 재사용하지 않는다.
확인 근거는 `.work/fea-prefix40-spectral-diagnostics/damping-source-audit.json`이다.

수정한 계수로 타워 요소 10개의 감쇠행렬을 다시 조립했다. 질량·강성행렬은
v6와 비트 단위로 같고, 블레이드·구동축·모노파일 감쇠는 그대로다. 다음은
무응력 정지 모델의 모드 감쇠비이며, 수정 후 운전 응답의 정확도 판정과 구분한다.

| 모드 | 수정 FEA 감쇠비 | 실제 OpenFAST 감쇠비 | 상대 차이 |
| --- | ---: | ---: | ---: |
| 첫 side-to-side | 0.0016025083 | 0.0015990142 | +0.219% |
| 첫 fore-aft | 0.0015763995 | 0.0015778256 | −0.090% |
| 구동계 | 0.0090926530 | 0.0089628947 | +1.448% |

모달 투영과 비대각 감쇠를 포함한 상태 고유값으로 교차 확인했다. 근거는
같은 폴더의 `source-damping-correction.json`과 NPZ다. 첫 fore-aft 계수를
타워 전체에 사용하는 근사는 유지하므로, ElastoDyn의 모든 고차 모드 감쇠를
정확히 재현했다고 주장하지 않는다. 부착 질량을 바꿔도 원 부재의 감쇠 계수를
다시 맞추지 않는 독립 조립·고유값 시험 3개가 통과했다.

## 구현과 변경 경계

신규 계산은 네 독립 Solver 패키지에 있다. 구조 요소·재료·조립·구속·풀이를
직접 구현했고 SciPy는 희소행렬, 선형계, 고유치 계산에 사용한다.
ABI 3, Geometry service, 공용 methods, UI와 Runtime 구조는 변경하지 않았다.
외부 수정은 Catalog 등록, SciPy 의존성/lockfile, 테스트에 한정했다.

코드를 읽는 순서와 물리적 의미는
[구조 알고리즘 안내](../../app/solvers/structural_mechanics/README.md)에 있다.
공력·수력·제어도 각 패키지의 README에 식·단위·적용 한계를 설명한다.
지원 조합과 실행 가능한 예제는 publish된 Catalog에서 조회한다.

## 마지막에 반영한 편심 보의 질량·중력 보정

보 전체의 공통 요소축으로 편심 질량을 회전시키면, 두 절점이 서로 다르게
변형될 때 중력이 하나의 위치에너지 미분과 일치하지 않을 수 있었다.
편심 무게중심의 속도를 각 절점의 `v + omega × (R*e)`로 계산하도록 고쳤다.
이 속도에서 질량과 그 미분을 함께 만들므로 병진 운동량과 중력도 같은
무게중심을 사용한다. 중앙 회전관성은 기존의 작은 상대변형 corotational
근사를 유지한다. 임의의 양의 정부호 행렬을 물리적인 유한회전 질량으로
오해하지 않도록 질량·편심·중앙 관성 조건도 검사한다.

격리 사본의 구조 회귀 165개와 최종 작업 폴더의 관련 검사 42개가 통과했다.
후자에는 편심 보의 변형 중 무게중심 운동량, 중력, 에너지, 질량 미분,
병진 기준속도 변경, 선형/유한회전 입력 구분과 혼합 요소 조립이 포함된다.
검사 집합은 일부 중복되므로 두 숫자를 더한 시험 수로 보고하지 않는다.
수정한 코드와 시험의 Ruff 검사도 통과했다.

v7 터빈의 블레이드 단면 54개는 모두 편심 질량 결합항이 정확히 0이다.
그 경로의 수치 연산은 유지했고, 수정 전후 0.1초 실행의 Record 배열 31개,
native SI 배열 15개, 비교 SI 배열 17개와 Task 47회의 수치 관측값이 모두
정확히 같았다. 근거는 `.work/fea-mass-correction-equivalence.json`이다.
이 짧은 동등성 검사를 장시간 정확도 판정으로 확대하지 않는다. 아래 v7의
8초·40초 결과는 이 마지막 보정 전에 얻은 자료임을 유지한다.

## 기존 실행 경로와 회귀

기존 CPU 회귀는 **323 passed, 2 deselected, 2 subtests**였다. Catalog Python
검사는 **17 passed, 10 subtests**, UI의 Catalog 컴파일·평가·build는 예제 16개가
통과했다. 실제 실행 검사는 15개 nominal 예제와 실제 child의 취소/외부 모델
artifact 실패 2개를 포함한다. 별도 기존 FCC CPU 예제도 회귀에서 실행했다.

최종 v8 Catalog와 보정한 코드의 0.1초 터빈 CLI 실행은 child 47회,
Record 4개, 실제 시간 표본
21개를 생성했다. 기록 payload는 268,796 bytes, 결과 폴더는 381,012 bytes였고,
Solver 시간 55.689초/CLI wall time 58.248초였다. 실제 CLI 종료 코드는 0이었다.
child 47개 모두 exit 0과 cleanup을 확인했다. 같은 Task를 반복 실행하고
마지막 확정 이력을 한 번 기록했으며, 실제 mmap 전달·ACK·release를 사용했다.
근거는 `.work/fea-v8-child-evidence/verification.json`이다. 최종 입력·Catalog와
실행 중 수치 소스 32개의 hash를 확인했고, 저장된 수치 배열 31개는 선행 v7 실행과
정확히 같았다. 이 CLI의 최종 live-resource 개수는 공개 출력에 없으므로,
별도 실제 child 자원 검사 결과와 구분한다.

기존 Calculation 실행기에서 일곱 채널을 읽어 수치 배열을 독립적으로 비교했고,
PNG 일곱 장을 렌더링해 육안 확인했다. 실제 Record에는 물리 단위와 시간 축이
보존된다. 기존 독립 PNG 렌더러의 Y축 표시는 `Value (unitless)`이며, Calculation의
표시 단위는 Catalog 이름/설명에 명시했다. 공유 렌더러 계약은 변경하지 않았다.

## 실제 OpenFAST 비교

아래 구성요소 검증은 실제 프로그램을 실행한 결과다. 저장소의 기존 `.outb`를
정답으로 읽거나 재현 결과를 대신 만들어 사용하지 않았다.
native replay는 v6 검증 당시의 built와 고정한 수치 소스로 수행했다. 사용한
built·수치 소스 사본과 각 실제 기준해의 hash는 `.work/fea-components-final-v6`에
따로 보존하며, 이전 비교 파일을 덮어쓰지 않았다.

| 독립 검증 | 차이 |
| --- | --- |
| 세 운전점, 원본 offset을 유지한 강체 블레이드 공력 | 추력 평균 ≤0.018%, 회전축 토크 평균 ≤0.074% |
| 실제 발전기 속도를 입력한 300초 제어기 replay, 마지막 60초 | 토크 최대 ≤0.84 N·m, 피치 최대 ≤1.42×10⁻⁶ rad |
| 정지 구조의 16초 Airy/Morison | 수평 합력 평균 +0.0157% 이내, 진폭 +0.0162% 이내 |
| 첫 지지구조 모드 | side-to-side −0.436%, fore-aft −0.451% |
| 구동계 모드 | −0.722% |

고정된 입력의 실제 300초 기준해 세 개와 바람 변화 40초 기준해가 정상 종료했다.
native와 초기 과도응답을 맞추기 위해 별도의 `unstrained` 모델에서 비교한다.
공식 초기 사전 변형을 유지한 결과와 혼용하지 않는다.

초기 8초의 전체 결합 결과는 세 풍속에서 유한한 운동·제어·하중 이력을 생성했다.
이는 한 바퀴 이상 회전하는 운전 검사이지만 정상상태 판정은 아니다. 특히 시작 직후
기초 수평력 진폭은 기준해보다 작았다. 실제 기준 절점 가속도를 native Morison에
넣은 조사에서 차이 대부분이 구조 가속도에 의한 부가질량 반력임을 확인했다.
서로 다른 타워/하부구조의 고차 모드와 중력 초기 진동을 구분해 조사했으며,
그 차이를 숨기거나 허용값을 늘리지 않았다. 상세 결과와 재현 명령은
[기준해 안내](README.md)에 있다.

## 수정 후 v7의 초기 8초 비교

정격 조건을 t=0부터 다시 계산해 실제 OpenFAST의 같은 초기 구간과 비교했다.
회전수 진폭 차이는 v6의 −10.24%에서 −0.507%로 줄었다. v7의 발전전력·타워
상단 변위·블레이드 끝 처짐 진폭 차이는 각각 +0.0359%, +0.434%, +3.175%다.
회전수와 타워 변위의 전체 파형 RMS 차이도 줄었다.

시작 직후 중력에 의한 고주파 응답은 여전히 다르다. 이 구간의 기초 수평
반력 진폭 차이는 −21.18%로 10% 기준을 넘는다. 수정 전 −29.27%보다는 작지만,
이를 합격으로 표시하거나 타워 감쇠 교정으로 모든 차이가 해결됐다고 하지 않는다.
정상 운전의 최종 판정은 후속 240–300초 구간 검증으로 남긴다. 원시 비교와
직접 확인한 파형 그림은 `.work/fea-v7-startup-comparison`에 있다.

같은 v7 입력으로 초기 0–8초를 t=0부터 다시 실행해 내부 간격을
0.005→0.0025초로 줄였다. 1,601개 공통 시간 표본의 일곱 채널 모두
2% 기준을 통과했다. 최대 차이는 기초 수평 반력의 1.11663%이며,
발전전력은 0.09737%, 블레이드 끝 처짐은 0.00805%였다. 감쇠가 더 작은
수정 입력의 민감도가 v6보다 커진 사실을 그대로 기록한다. 기준 실행과
절반 간격 실행의 wall time은 각각 567.808초, 996.453초였다.
근거는 `.work/fea-convergence-rated-v7/halfdt-convergence.json`이다.
연성 구간을 0.05→0.025초로 줄인 검사도 일곱 채널 모두 통과했다.
최대 차이는 기초 수평 반력의 0.000148477%였고 wall time은 424.606초였다.
세 실행 모두 구조 잔차 ≤10⁻⁸, 채택한 연성 잔차 ≤10⁻⁴를 유지했다.
입력 단위·축·수치 소스·런타임과 네 Task의 최종 확정 상태도 독립적으로
검사했다. 추가 근거는 같은 폴더의 `halfwindow-convergence.json`과
`final-audit.json`이다. 이 결과를 예열 후 모든 운전점의 수렴 증명으로
확대하지 않는다.

변화 2% 검사다. 이 판정은 아직 통과한 것이 아니다. 완료한 짧은 검증과
기본 실행 검사는 위에 별도로 기록했다.

## 재현과 읽어야 할 한계

저장소 루트 PowerShell에서 다음은 publish된 예제의 짧은 실제 child 실행이다.
출력 폴더에는 아직 사용하지 않은 경로를 지정한다.

```powershell
.\caemble.cmd doctor
.\caemble.cmd catalog show solver structural-mechanics --version 1.0.0
.\caemble.cmd experiment init .work/operating-source --example nrel5mw-oc3-operating
.\caemble.cmd experiment build .work/operating-source --vars-mode nominal --out .work/operating-built
.\caemble.cmd experiment test .work/operating-built --out .work/operating-result --timeout 3600
```

긴 수치 실행, 실제 OpenFAST 실행, 비교/수렴 도구의 명령은 [README](README.md)에
있다. `--in-process`는 수치 비용을 줄이기 위한 검증 도구 옵션이며 실제 child
전달 검사의 대체가 아니다. 서버 배포나 실제 풍력터빈의 설계 인증은 수행하지 않았다.

적용 한계는 다음과 같다.

- 큰 회전은 작은 탄성 변형률의 corotational 보·쉘 범위다. 솔리드 J2를 유한변형
  소성으로 취급하지 않는다. 임의 CAD 자동 메시, 마찰, 자기접촉, 손상·균열 성장은 없다.
- 공력은 정렬된 유입과 고정된 명목 회전축 방향을 사용한다. 일반적인 큰 yaw나
  동적 실속, 난류를 검증한 모델로 표시하지 않는다. 회전자 운동은 구조가 소유한다.
- 기준 ElastoDyn 타워와 native 전체 보 타워의 자유도 집합은 완전히 같지 않다.
  타워 비틀림과 결합한 일부 블레이드 모드는 차이가 남으며 기본 모델을 숨겨 조정하지 않았다.
- 수력은 기준 젖은 구간의 Airy/Morison 모델이다. 파면에 따른 일반적인 wet/dry 전환,
  방사·회절, 부유체/계류나 비선형 지반 모델을 포함하지 않는다.
- 쉘·솔리드 상세 예제는 같은 순간의 외력을 보존해 옮긴 준정적 응답이다.
  자중·구조 관성까지 포함한 전체 모델의 절단면 내부력을 그대로 복원한 결과는 아니다.
- 일반화 보 단면 K/M/D는 자체 물성이다. 기본 CAD 재료의 E·밀도로 덮어쓰지 않으며,
  이 행렬만으로 복합재 층별 내부 응력을 임의 복원하지 않는다.
