# 실제 해석으로 변수 최적화하기

**최적화**는 현재 Candidate에서 시작해 Vars를 바꾸고 실제 Solver를 반복 실행하며 목적값을 개선합니다. 한 번의 탐색을 **Optimization**, 한 후보의 평가를 **Trial**이라고 합니다. 각 Trial은 빌드, 해석, 후처리 순서로 진행하며 성공한 해석 결과는 Measurement로 남습니다.

## 진행 중인 최적화 확인하기

**최적화** 탭을 열면 저장된 Optimization 목록과 선택한 항목의 진행 상태를 먼저 확인합니다. 현재 Candidate를 준비하거나 다시 실행하지 않아도 기존 이력을 볼 수 있습니다. 목록에서 항목을 선택하면 평가 수, 현재 단계, 최선 후보와 Trial 이력이 표시됩니다. **Setting**에서는 상태·평가 수·최선 목적값과 제어 버튼을 간략히 보고 **Workbench에서 열기**로 상세 화면에 진입합니다.

목록에서 선택한 항목은 상태가 갱신되어도 유지됩니다. 직접 링크의 `?optimization=<id>`로 항목을 열거나 브라우저의 뒤로·앞으로 이동으로 이전 선택을 다시 볼 수 있습니다.

## 새 최적화 시작하기

1. 편집 권한이 있는 Experiment를 저장하고 **최적화** 탭에서 **새 Optimization**를 엽니다. 소스에 저장하지 않은 변경이 있으면 먼저 저장하세요. 현재 Candidate를 복원하는 동안에는 복원이 끝난 뒤 설정할 수 있습니다.
2. 현재 Candidate의 Vars를 시작 조건으로 확인합니다. 모든 스칼라와 Tensor의 모든 원소가 기본 탐색 대상이며, 범위는 Experiment의 Vars 규격에서 가져옵니다.
3. 바꾸지 않을 변수는 **탐색**을 해제합니다. Tensor는 **원소별 범위·고정**을 펼쳐 각 원소의 탐색 여부와 범위를 따로 정할 수 있습니다. 고정한 값은 시작 Candidate의 값을 유지합니다. 범위를 줄일 때도 시작값을 포함해야 합니다.
4. 저장된 Calculation을 목적값으로 고르고 **최소화** 또는 **최대화**를 선택합니다. 필요하면 다른 Calculation의 하한·상한을 제약조건으로 추가합니다.
5. 최대 평가 횟수와 동시 후보 수를 정하고 **최적화 시작**을 누릅니다.

설정은 오른쪽 패널에서 열리며 작은 화면에서는 전체 화면으로 표시됩니다. 같은 Experiment와 소스의 작업 중에는 패널을 닫았다 다시 열어도 입력한 설정이 유지됩니다. 생성이 끝나면 패널이 닫히고 새 Optimization의 진행 화면으로 이동합니다.

목적값과 제약조건은 각각 유한한 숫자 스칼라여야 합니다. 아직 출력 검증을 하지 않은 저장된 Calculation도 선택할 수 있으며, 첫 Trial의 실제 결과로 검증합니다. 별도의 사전 해석은 필요하지 않습니다. 첫 Trial은 현재 Candidate를 평가하므로 최대 평가 수에 포함됩니다.

하한과 상한이 같은 원소도 고정값으로 취급합니다. 모든 변수를 고정하면 시작 Candidate 한 번을 평가하고 완료합니다. 고정한 원소도 범위 안에 시작값이 있어야 합니다.

Optimization은 시작할 때의 Experiment 소스, Calculation과 변수 범위를 고정합니다. 기존 Optimization을 새 설정으로 바꾸려면 새 Optimization을 시작하세요. Optimization이 참조하는 Experiment 소스를 바꾸려면 **Save As**로 새 Experiment를 만들거나 해당 Optimization 이력을 먼저 삭제해야 합니다.

## 진행 상태와 실패 확인하기

목록에서 Optimization을 선택한 뒤 Trial을 펼치면 빌드·해석·후처리 단계와 각 제출 이력, Job 상태, 자원 대기와 오류를 확인할 수 있습니다. Optimization에 속한 실행은 이 그룹 안에 표시되며 일반 Batch·Job 목록과 중복되지 않습니다.

한 Trial이 실패하면 새 평가 진행을 멈춥니다. 이미 실행 중인 작업의 종료와 자원 정리가 끝날 때까지 **중지 중**으로 표시될 수 있습니다. 실패한 Trial의 오류를 확인한 뒤 **실패 단계 재시도**를 누르세요. 성공한 앞 단계는 보존하고 실패한 단계부터 다시 실행합니다. 재시도가 완료되고 남은 실패가 없어지면 **재개**로 전체 탐색을 계속합니다. 재시도 중이거나 이전 프로세스를 정리하는 동안에는 다시 제출할 수 없습니다.

**Trial 수**와 **수동 재시도 횟수**는 따로 표시합니다. 수동 재시도는 새 Trial 예산을 사용하지 않으며, Job을 제출하기 전에 실패했더라도 접수된 재시도 횟수에 포함됩니다. 단계 안의 제출 이력은 실제로 생성된 Job을 보여 줍니다.

**중지**는 실행 중인 작업도 취소합니다. 자원 정리가 끝난 뒤 **재개**하면 아직 완료하지 않은 단계부터 계속합니다. 같은 후보를 중복 생성하지 않고 기존 Trial 이력에 이어서 기록합니다.

브라우저를 닫거나 다른 화면으로 이동해도 Optimization은 계속됩니다. 실제 실행에는 서버와 사용 가능한 Launcher가 필요합니다. Launcher가 꺼져 있거나 필요한 자원이 없으면 대기 상태가 이어지며, Launcher를 다시 연결하면 실행할 수 있습니다. 브라우저를 다시 여는 것만으로 Launcher가 시작되지는 않습니다.

## 최선 후보 적용하기

제약조건을 만족한 평가 중 목적값이 가장 좋은 결과가 **최선 후보**에 표시됩니다. **최선 Vars로 새 Candidate 열기**를 누르면 Optimization에 고정된 소스와 해당 Vars를 함께 엽니다. 현재 작업에 저장하지 않은 소스 변경이 있으면 기존 전환 확인 절차를 따릅니다. 다른 Experiment를 보고 있더라도 최선 Vars를 그 소스에 섞어 적용하지 않습니다.

이 동작은 새로운 Candidate를 여는 것이며 자동으로 다시 해석하거나 기존 Measurement를 바꾸지 않습니다. 필요한 경우 Experiment 화면에서 조건을 확인하고 직접 저장·실행하세요. **Setting**에서는 **Workbench에서 열기**로 이동한 뒤 적용할 수 있습니다.

중지 또는 완료된 Optimization의 **삭제**는 Optimization과 Trial 이력을 지웁니다. 이미 저장된 Measurement는 유지됩니다. 작업이 실행 중이거나 자원을 정리하는 동안에는 삭제할 수 없습니다.
