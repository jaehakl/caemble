# 원격 Prediction으로 BoxGrid 예측하기

**Prediction**은 Candidate의 Vars를 원격 저장 모델에 넣어 하나 이상의 BoxGrid를 예측합니다. 현재는 CPU kNN 모델을 사용합니다. Calculation은 예측 결과에 적용하는 선택적 후처리이며, 선택하거나 실행하지 않아도 BoxGrid를 확인할 수 있습니다. 목표값·제약조건으로 설계 변수를 찾는 작업은 Optimization의 역할입니다.

## 예측을 처음 사용한다면

1. 저장된 Experiment의 **Prediction** 탭을 엽니다. 다른 탭을 먼저 실행할 필요는 없습니다.
2. 사용할 **모델**과 revision을 고르고 실행할 **Launcher**를 확인합니다. 저장 모델이 없으면 **데이터·모델 관리**에서 만듭니다.
3. 모델이 지원하는 출력 중 예측할 **BoxGrid**를 하나 이상 선택합니다.
4. Vars를 편집하면 현재 Candidate의 격자 준비 후 자동으로 예측합니다. **예측** 버튼으로 같은 조건을 다시 실행할 수도 있습니다.
5. Viewer에서 예측 결과를 확인합니다. 필요하면 Calculation을 선택해 분석하거나 **Save & Run**으로 실제 결과와 비교합니다.

원격 실행에는 로그인과 Predictor가 설치된 내 Launcher가 필요합니다. 공개 Demo의 저장 결과·소스·Calculation·Analysis는 기존 권한으로 열람할 수 있지만, 비로그인 원격 예측 체험은 제공하지 않습니다. 원격 연결이 실패해도 브라우저 예측으로 전환하지 않습니다.

새로고침하면 같은 계정·Experiment의 저장 모델 참조, 실행 위치, 출력 및 선택적 Calculation 설정을 복원합니다. 이전 실행 세션의 handle은 복원하지 않으며 저장 모델을 새 세션에 로드합니다. 일반 공유 URL에는 `?experiment=ID`를 저장합니다. 탭과 Measurement·Calculation 선택은 URL에 담지 않습니다.

## Vars 변경과 자동 예측

Vars 편집기의 유효한 입력이 확정되면 Candidate가 바뀝니다. 해당 Candidate의 BoxGrid 좌표·크기·회전 준비가 끝나면 원격 예측을 실행합니다. 연속된 변경에서는 최신 입력만 반영하며 이전 응답이 늦게 도착해도 현재 결과를 덮어쓰지 않습니다.

**취소**는 현재 요청의 결과 반영과 후처리를 중단합니다. 원격 계산의 즉시 강제 종료를 의미하지 않으며 저장 모델은 유지합니다. 같은 요청이 화면 갱신이나 탭 재진입만으로 다시 시작되지는 않습니다. Vars·모델·출력을 바꾸거나 **예측**을 누르면 다시 실행합니다. 실패한 요청도 원인을 확인한 뒤 재시도하세요.

모델은 Vars·Calculation·화면 변경마다 다시 학습하지 않습니다. 같은 모델 revision의 인스턴스를 재사용하며, 사용하지 않는 원격 세션은 5분 뒤 자원을 반환합니다. 다음 예측에는 같은 저장 파일을 다시 로드합니다.

### Prediction Viewer

본문은 선택한 BoxGrid의 예측 결과를 표시합니다. 현재 Candidate의 위치·크기·회전과 셀 중심 좌표가 결과에 반영됩니다. 메시·광선 경로 등 Solver의 별도 시각화 결과는 예측하지 않습니다.

**예측**과 **실제 결과**는 별도로 표시합니다. 예측 결과에는 Candidate와 Model·Dataset revision의 출처가 연결되며 실제 RecordedData나 학습 관측값으로 자동 저장되지 않습니다. 현재 Candidate·모델·출력 선택과 다른 이전 결과를 현재 예측처럼 표시하지 않습니다. 갱신 중에도 Viewer의 카메라와 표시 설정은 유지합니다.

Calculation이 실패해도 성공한 BoxGrid 예측은 남습니다. Geometry를 겹칠 때는 결과와 source·Vars가 일치하는 형상만 사용합니다. 실제 Solver 결과는 해당 Measurement의 문맥으로 표시합니다.

### 선택적 Calculation

Calculation은 예측 BoxGrid에 기존 계산식을 적용하는 분석 기능입니다. 필요한 출력의 **자동 선택**은 편의 기능이며 Calculation 선택 자체가 모델 생성이나 예측의 선행 조건은 아닙니다.

Calculation을 바꾸면 현재 예측 결과로 후처리만 다시 실행합니다. 모델이 필요한 출력을 제공하지 않으면 해당 출력을 지원하는 모델을 선택해야 합니다. 모델이 제공하는 출력이 선택에서 빠졌다면 필요한 출력을 추가하세요. Calculation의 소스·출력 규격 오류는 해당 분석에 표시하며 다른 예측 결과를 지우지 않습니다.

## Settings와 cohort

실행 영역에는 모델·알고리즘·revision·Launcher·준비 상태를 표시합니다. k와 이웃 가중치 설정은 관리 패널에서 **새 모델 버전**을 만들 때 사용합니다. 기존 모델을 사용할 때 다시 입력할 필요가 없습니다. 목표값·제약조건·Calculation별 가중치는 Prediction 모델 설정에 포함하지 않습니다.

**cohort**는 함께 학습할 수 있는 표본 묶음입니다. kNN은 선택한 Record의 7차원 BoxGrid 전체를 사용합니다. shape·dtype·물리 단위·채널과 성분 순서·관측 방식·시간과 일반 주파수 계약이 호환되는 표본을 묶고 가장 큰 묶음을 사용합니다. 동률이면 가장 낮은 Measurement ID를 포함한 묶음을 고릅니다.

Box의 위치·크기·회전과 공간축 좌표는 표본마다 달라도 됩니다. 기존 Box 내부 상대 셀 대응을 사용하며 새로운 좌표 보간이나 단위 변환은 하지 않습니다. 지원하지 않는 차이는 Record별 사유로 표시합니다. Dataset revision과 checksum 검증은 파일 무결성 검사이며 표본 간 좌표 일치 조건이 아닙니다.

모달 출력은 같은 Task의 장과 고유주파수를 하나의 최근접 Measurement에서 함께 가져오며 고유벡터를 평균하지 않습니다. 복소수는 진폭·위상을 실수부·허수부로 변환하여 계산한 뒤 복원합니다. 진폭이 0이면 위상도 0입니다.

**Auto k**는 학습 행 수 `n`의 `round(sqrt(n))`을 1~15와 해당 묶음 크기 안으로 제한합니다. **Manual k**는 묶음 크기 안의 양의 정수입니다. **Distance**는 가까운 이웃에 큰 가중치를 주고 **Uniform**은 같은 비중을 줍니다. Vars 거리는 varsSchema 범위로 정규화합니다. Predictor는 배정된 CPU·RAM 안에서 준비 가능 여부를 검사합니다.

Console의 **Prediction**과 모델 세부 정보에서 포함·제외된 표본, 출력 오류와 모델 출처를 확인하세요.

## 원격 Dataset과 저장 모델

**데이터·모델 관리**에는 모델, 학습 데이터와 관리 작업을 모았습니다. 저장 모델이 있으면 모델 생성 절차를 반복하지 않고 바로 선택할 수 있습니다. Launcher가 연결되지 않아도 API에 등록된 자산 목록은 확인할 수 있습니다.

새 모델은 예측할 Record와 학습 Dataset revision, kNN 설정, 학습 장비를 선택해 만듭니다. 새 Forward Dataset은 Measurement·RecordedData를 사용하며 CalculationData를 요구하지 않습니다. 큰 서버 데이터는 학습 프로세스가 제한된 읽기 권한으로 직접 내려받습니다.

접수한 학습은 서버와 Launcher가 실행하므로 화면이나 브라우저를 닫아도 계속됩니다. **작업**에서 대기·진행·완료 상태를 확인하고, 다시 접속하면 진행 중인 학습을 다시 조회합니다. 학습 대기부터 프로세스 정리가 끝날 때까지 사용 중인 Dataset의 갱신·삭제는 차단됩니다.

완성 모델의 저장과 등록이 모두 성공하면 별도 예측 세션에서 모델을 로드합니다. 같은 화면에서 학습을 시작한 뒤 선택을 바꾸지 않았다면 새 모델로 전환합니다. 그동안 다른 모델을 선택했거나 브라우저를 다시 열었다면 현재 선택을 보존합니다. 새 버전 학습이 실패해도 기존 완성 버전은 유지합니다.

**이 작업 중단**은 서버에 학습 취소를 요청합니다. 프로세스 정리가 끝난 후 자원을 반환하고 Dataset 갱신이 다시 가능해집니다. 실패한 작업은 같은 작업의 **상태 확인·다시 시도**로 재시도하세요. 완성 파일만 남아 있다면 원본 Dataset 없이 등록을 복구하며, 파일이 없으면 당시 Dataset revision을 확인하여 처음부터 학습합니다. 중간 학습 상태의 저장·재개는 지원하지 않습니다.

Dataset과 모델 revision은 명시적으로 갱신하기 전까지 고정됩니다. **새 데이터 확인**과 **학습 데이터 갱신**으로 원본 변경을 반영한 뒤, 모델의 **새 버전 만들기**로 학습합니다. Dataset 갱신만으로 선택 모델을 바꾸거나 재학습하지 않습니다. 저장 모델에는 추론에 필요한 정보가 있으므로 원본 Dataset을 사용할 수 없어도 모델 복사본으로 예측할 수 있습니다.

기존 Forward 모델·Dataset·백업은 그대로 사용합니다. 기존 Inverse 모델은 관리 화면에서 **지원 종료**로 표시하며 실행 모델 목록에서 제외합니다. 자동 변환하거나 삭제하지 않고 조회·백업·복원 등 보관 관리를 유지합니다.

### 백업·복원과 파일 관리

**백업하기**는 기본으로 모델을 보관합니다. 학습 원본도 필요하면 **학습 데이터 rN 원본도 포함**을 선택하세요. 해당 모델이 사용한 정확한 Dataset revision이 필요하며 최신 데이터로 대신 채우지 않습니다.

**복원**은 같은 ID·revision·checksum의 파일을 선택한 장비에 저장합니다. 모델을 재학습하지 않습니다. 백업 자체에서는 예측할 수 없으므로 실행할 Launcher가 접근할 수 있는 저장소에 복원해야 합니다. **복원하고 사용**은 지원되는 Forward 모델의 복원·검증 후 실행 위치를 전환합니다.

관리 패널을 닫아도 시작한 작업은 계속됩니다. 브라우저 종료 후에도 접수된 모델 학습은 계속되며, 브라우저 연결을 사용하는 백업·복원이 중단되면 같은 작업을 재시도하세요. **작업**에서 진행 상태·중단·실패 후 재시도를 확인하세요. 관리 작업은 예측 세션과 독립적입니다.

**Setting → 모델 파일 관리**에서는 내 모든 Experiment의 모델·revision·저장 위치별 복사본을 확인합니다. 검색·필터·정렬과 파일 확인을 사용하고, 파일명·길이·checksum을 확인할 수 있습니다. 등록 용량은 현재 디스크 점유량이나 최신 검증 결과와 다를 수 있습니다.

**이 위치에서 제거**는 선택한 복사본을 삭제합니다. **모델 전체 삭제 요청**은 모든 revision과 복사본을 삭제 대상으로 지정합니다. Dataset 삭제는 저장 모델과 원본 Measurement·RecordedData·CalculationData를 유지합니다. 인스턴스 해제나 예측 취소는 저장 파일 삭제가 아닙니다.

외부 파일 가져오기는 출처를 보존하는 새 Dataset을 생성하며 백업 복원과 구분됩니다. [Predictor 설치와 Dataset 파일 준비](../../operations/workers.md#predictor-datasets-and-saved-models)를 참고하세요.

## 실행 상태 확인하기

| 상태                         | 확인할 사항                                                     |
| ---------------------------- | --------------------------------------------------------------- |
| 연결 끊김                    | 내 Launcher와 Predictor 실행 가능 상태를 확인하고 재연결합니다. |
| 접근 가능한 모델 복사본 없음 | 해당 Launcher에서 접근할 복사본을 선택하거나 백업을 복원합니다. |
| 자원 대기                    | Launcher의 CPU·RAM 반환 및 배정 상태를 확인합니다.              |
| 모델 로드 실패               | 오류에 표시된 파일·checksum·계약·지원 버전을 확인합니다.        |
| 시간 초과                    | 연결 또는 작업 상태를 확인한 뒤 명시적으로 재시도합니다.        |

다른 Launcher나 브라우저로 자동 전환하지 않습니다. 연결 복구 시 이전 세션 handle을 재사용하거나 자동으로 새 모델을 학습하지 않습니다.

## Save & Run 검증

편집 가능한 내 Experiment에서 현재 Candidate를 저장하고 실제 Solver로 실행하여 예측과 비교합니다. 새로운 무작위 후보를 만드는 동작은 아닙니다. 실제 실행에는 저장된 Experiment와 기존 실행 권한이 필요합니다.

Calculation 없이도 실제 BoxGrid와 비교할 수 있습니다. 선택한 Calculation이 있으면 실제 결과의 후처리도 비교합니다. 같은 shape의 Calculation 결과는 같은 배열 인덱스로 MAE·RMSE·최대 절대 오차를 계산하며, 좌표 보간이나 단위 변환은 하지 않습니다.

여러 실제 후보가 필요하면 Measurement의 [일괄생성](workbench-measurement.md#일괄생성)을 사용하세요.
